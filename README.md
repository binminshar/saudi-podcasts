# بودكاست السعودية

تطبيق عربي RTL باستخدام Next.js 15 وReact 19 وTypeScript، مع لوحة إدارة فعلية على `/admin`.

## لوحة التحكم والحفظ

## نقل الموقع والدومين

تُعامل مواد موقع المالك السابقة (176 مادة) كمنشورات محلية باسم «بودكاست السعودية»، مع حفظ المقالات والصور وتواريخ النشر السابقة. تحفظ الروابط السابقة في `legacyUrl` لأغراض التحويل، وتعمل الفيديوهات داخل الموقع. يظل محتوى مايكس وثمانية منسوبًا إلى ناشريه.

النطاق الأساسي الافتراضي هو `https://saudi-podcasts.com`. تتضمن البيانات المنظمة اسم المنصة كناشر للمواد المحلية. يوفر middleware تحويلات 301 لـ176 رابط منشور سابق و171 صورة، وروابط WordPress بصيغة `?p=ID`، وصفحات التصنيفات والصفحات المرقمة، وfeed القديم إلى `/feed.xml`. يمكن إعادة إنشاء الخريطة عبر `node scripts/build-legacy-routes.mjs`. يُختبر التحويل محليًا، ولا يغيّر ذلك إعدادات DNS أو استضافة الدومين الحالي.

للنشر الخارجي استخدم استضافة Node.js بقرص دائم لمجلد `.data`، وانقل بياناته وصوره مع المشروع، واضبط HTTPS ثم وجّه DNS الدومين إلى الاستضافة. لا تنقل ملفات `.data` إلى مجلد عام. لم تنفذ هذه الجلسة نشرًا خارجيًا أو تعديل DNS؛ الموقع المتاح حاليًا هو localhost.

تُعرض المواد المنشورة من مختلف المصادر بترتيب عشوائي ثابت في واجهات الاكتشاف، مع بقاء المثبت أولًا في الرئيسية. لا يغيّر الخلط تواريخ النشر الأصلية أو ترتيب الأكثر مشاهدة وشيوعًا. تبقى خيارات الفرز بالتاريخ في لوحة الإدارة متاحة.

## استيراد saudi-podcasts.com

بناءً على تصريح المستخدم بملكية الموقع أو الإذن بإعادة النشر، أضيفت 176 مادة منشورة من جميع تصنيفات المصدر بتاريخ 19 أكتوبر 2026، واستُبعد منشور WordPress التجريبي Hello world. تشمل 9 مقالات بنصوصها المتوفرة كاملة و176 فيديو يوتيوب، وصورًا مصغرة محلية وتواريخ النشر الأصلية. لا يُقدَّم المقال التحريري على أنه تفريغ حرفي للصوت، وتُعرض الفيديوهات عبر إطار يوتيوب مقيد دون تشغيل HTML المصدر. التصنيف «الرئيسية» يطابق «أخرى» محليًا مع حفظ أسماء التصنيفات الأصلية في البيانات.

البيانات في `app/saudi-episodes.json`. أُضيف مصدر مستقل في اللوحة وتُدمج المجموعة مرة واحدة مع البيانات المحفوظة. يحتفظ السجل بعلامة الاستيراد لمنع عودة المواد بعد حذفها، وتبقى المقالات والصور والتواريخ السابقة المعدلة يدويًا محفوظة. إجمالي البداية بعد الإضافة 276 مادة. فحص التكامل يتحقق من العدد والنصوص والتواريخ والصور وعمليات الإدارة.

تتوفر للحلقات المئة تواريخ النشر الأصلية وصور محفوظة محليًا في `public/thumbnails`؛ يُستخدم غلاف البرنامج الرسمي لحلقة صوتية واحدة. الترتيب الافتراضي بحسب تاريخ النشر الأصلي، مع أولوية التثبيت. يعرض جدول الإدارة التاريخ وحالة النص، ويدعم الفرز بالتاريخ أو آخر تعديل والتصفية بالمصدر وبوجود التفريغ. داخل محرر الحلقة يمكن تغيير تاريخ النشر المعروض والصورة والمقال، مع إبقاء تاريخ المصدر الأصلي مستقلًا، واستيراد ملف TXT أو Markdown، وتحديد النص كملخص أو تفريغ كامل.

التفريغات الكاملة لم تُستورد. المتوفر مقتطفات تعريفية قصيرة وروابط المصادر، موسومة بوضوح. تُضاف النصوص الكاملة المرخّصة من المحرر ولا يُقدَّم المقتطف على أنه تفريغ للتسجيل. يمكن حذف الحلقة أو أرشفتها من جدول الحلقات؛ الحذف يشمل نصها وبياناتها ويُخفيها عن الموقع، أما الصور المشتركة المحفوظة فلا تُحذف تلقائيًا.

تُستكمل بيانات المصدر الناقصة للسجلات القديمة دون إعادة إضافة حلقات سبق حذفها، ودون استبدال المقالات أو الصور المخصصة أو التواريخ المعدلة يدويًا. لتحديث بيانات المصدر استخدم أدوات الاستيراد بحذر مع نسخة احتياطية؛ بيانات الإدارة المحفوظة تبقى المرجع للتعديلات اليدوية.

افتح http://localhost:3000/admin وسجّل الدخول باسم المستخدم وكلمة المرور. عند الإعداد الأول اختر اسم مستخدم من 3 إلى 40 حرفًا إنجليزيًا أو رقمًا، وكلمة مرور من 12 حرفًا على الأقل. الإعداد الأول محلي فقط، ولا توجد كلمة مرور افتراضية. الجلسة محمية وتستمر 8 ساعات. كلمات المرور محفوظة بصيغة مشتقة ولا يمكن استرجاع نصها.

اللوحة تدير الحلقات والمصادر والكتّاب، مع إضافة وتعديل ونشر وأرشفة واستعادة وحذف، ورفع صور، ومحرر مقال كامل ومعاينته، وإعدادات SEO. تدعم تثبيتًا مستقلًا للرئيسية والأكثر مشاهدة والأكثر شيوعًا؛ الرقم الأقل أولوية يظهر أولًا. يظهر المنشور فقط للزوار. تاريخ النشر تحريري وليس جدولة آلية.

يحفظ التطبيق البيانات على الخادم في `.data/catalog.json`، وبيانات دخول المدير في `.data/admin-auth.json`، والصور في `.data/uploads`. المجلد مستبعد من Git ويجب نسخه كاملًا عند النقل أو النسخ الاحتياطي. يمكن تغيير المسار عبر `CATALOG_DATA_DIR`. يتطلب قرصًا دائمًا قابلًا للكتابة وخادمًا واحدًا؛ الاستضافة المؤقتة أو متعددة المثيلات تحتاج تخزينًا مشتركًا قبل النشر. لم يُنشر على استضافة خارجية.

تُحسب مشاهدة الحلقة مرة لكل متصفح خلال 30 دقيقة بملف ارتباط مؤقت. العداد إرشادي ولا يمثل زوارًا فريدين. غير المثبت في قائمة الأكثر مشاهدة يرتب بمشاهدات الموقع، وفي الأكثر شيوعًا بأعداد المصدر المتوفرة. التقييم إرشادي مستوحى من [مبادئ Yoast](https://yoast.com/features/seo-analysis/)، وليس إضافة Yoast أو ضمانًا للترتيب.

تُطبّق بيانات SEO وcanonical وnoindex على صفحات الحلقات من الخادم. أضف نطاق الموقع من الإعدادات لتفعيل روابط sitemap.xml. إضافة مصدر لا تستورد مكتبته تلقائيًا، والتفريغات الكاملة لا تزال تحتاج النص المراجع وحق نشره.

## التشغيل

```sh
npm install
npm run dev
```

افتح http://localhost:3000 . على PowerShell استخدم `npm.cmd` إذا منعت سياسة التنفيذ تشغيل npm.ps1.

## التحقق والبناء

```sh
npm run typecheck
npm run build
```

بعد البناء، شغّل `npm run start` لتشغيل خادم الإنتاج. الموقع أصبح تطبيق خادم وليس تصديرًا ثابتًا إلى out. افحص الوظائف الإدارية بعد البناء عبر `node scripts/smoke-admin.mjs`؛ يستخدم بيانات وخادم اختبار منفصلين ولا يضبط كلمة مرور حسابك.

## النشر: Supabase + GitHub + Render

التخزين يعمل بوضعين: بدون متغيرات Supabase يُحفظ كل شيء في `.data` محليًا، ومع ضبط `SUPABASE_URL` و`SUPABASE_SERVICE_ROLE_KEY` يُحفظ الكتالوج وبيانات الأدمن في جدول `site_documents` والصور المرفوعة في bucket خاص باسم `uploads` (انظر `app/lib/storage.ts`). هذا ضروري على Render لأن قرصه مؤقت ويُمسح مع كل نشر.

1. أنشئ مشروع Supabase ونفّذ `supabase/migrations/0001_site_documents.sql` في SQL Editor.
2. انسخ `.env.example` إلى `.env` وضع `SUPABASE_URL` و`SUPABASE_SERVICE_ROLE_KEY` (مفتاح service_role سري؛ لا يُستخدم في المتصفح ولا يُرفع إلى Git).
3. ارفع بياناتك الحالية: `npm run push:supabase` (يرفع `catalog.json` و`admin-auth.json` والصور؛ أضف `--force` لاستبدال حساب أدمن موجود).
4. ادفع الكود إلى GitHub ثم أنشئ Blueprint في Render من `render.yaml`، وأدخل متغيري Supabase في إعدادات الخدمة. إذا لم تنقل `admin-auth.json` يمكنك ضبط `ADMIN_USERNAME` و`ADMIN_PASSWORD` لإنشاء الحساب الأول تلقائيًا.
5. بعد النشر حدّث «نطاق الموقع» من إعدادات لوحة التحكم ليطابق الدومين النهائي؛ يعتمد عليه canonical وsitemap.xml وOpen Graph.

رؤوس الأمان (CSP وHSTS وX-Frame-Options وغيرها) مضبوطة في `next.config.ts`؛ عند إضافة مصدر خارجي جديد للسكربتات أو الإطارات أضفه إلى سياسة CSP.

## الصفحات والوظائف

الرئيسية، التصنيفات، الحلقات، تفاصيل كل حلقة، المكتبة، وعن المنصة. بحث وتصفية، مفضلة وملاحظات محفوظة في localStorage، مظهر فاتح وداكن، ومشغل صوت يدعم التقديم والرجوع والسرعة ومستوى الصوت.

## المحتوى المكتوب للحلقات

تعرض صفحة كل حلقة مقالًا أسفل معلوماتها، مع مقدمة وعناوين رئيسية وفرعية وفهرس روابط ومدة قراءة محسوبة. أضف النص المراجع من محرر الحلقة داخل لوحة التحكم. عند غياب النص تظهر رسالة انتظار إضافته؛ لا يُولّد تفريغ تلقائي من ملف الصوت في هذه النسخة.

## دليل الحلقات المستوردة

تحتوي المكتبة على 100 حلقة فعلية مفهرسة: 50 من مايكس في `app/mics-episodes.json` و50 من ثمانية في `app/thmanyah-episodes.json`. البيانات تشمل العنوان والبرنامج والتصنيف ورابط المصدر، مع وصف تعريفي أصلي قصير. التصنيفات محلية تحريرية لتلائم الموقع. يمكن التصفية بالناشر والتصنيف والبحث بالعنوان.

تفتح أزرار الاستماع للحلقات المستوردة صفحة الناشر الأصلية، ويمكن إضافة رابط صوت مباشر من اللوحة. لم تُنزّل التسجيلات أو التفريغات الكاملة ولم تُنسخ المقالات. صور مايكس روابط إلى الصور المتاحة في المصدر، وصور ثمانية الأولية تعبيرية وموسومة بذلك. غياب المدة يُعرض كعبارة «المدة على المصدر». قائمة الأكثر مشاهدة تعتمد على زيارات صفحات الموقع، وقائمة الأكثر شيوعًا تعتمد على ترتيب المدير ثم أعداد المشاهدة المتوفرة لدى المصدر.

جُمعت بيانات ثمانية من صفحات البرامج والحلقات عبر أداة التصفح. يمكن تحديث ملفات البذور لمايكس بتشغيل `node scripts/import-mics.mjs`؛ لا يغيّر ذلك نسخة الإدارة المحفوظة في `.data`. الصور الخارجية والخطوط تحتاج اتصالًا بالإنترنت. يوجد حساب مدير واحد حاليًا، بينما المفضلة والملاحظات تظل محلية لكل متصفح.
